# Система аутентификации и авторизации

## Что это за проект?

Это backend-приложение — собственная система аутентификации и авторизации,
написанная на FastAPI. Вместо PostgreSQL используются JSON-файлы для простоты.

```bash

pip install -r requirements.txt

# 2. Запустить сервер
uvicorn app.main:app --reload

# 3. Открыть Swagger UI
# http://localhost:8000/docs
```

## Схема авторизации (как работает система прав доступа)

### Главная идея

```
Пользователь → Роль → Разрешения → Ресурс + Действие
```

У каждого пользователя есть **одна роль**. У каждой роли есть **список разрешений**.
Каждое разрешение описывает **какой ресурс** и **какое действие** можно совершать.

### Таблицы (JSON-файлы)

#### 1. users.json — Пользователи

```json
{
  "id": "user-1",
  "first_name": "Админ",
  "last_name": "Админович",
  "patronymic": "Админов",
  "email": "admin@test.ru",
  "password_hash": "соль:хеш",
  "role_id": "role-admin",       // ← ссылка на роль
  "is_active": true,             // ← false = мягко удалён
  "created_at": "2024-01-01T00:00:00"
}
```

**Ключевые поля:**
- `role_id` — связывает пользователя с ролью (отношение Many-to-One)
- `is_active` — мягкое удаление: False = аккаунт "удалён", но данные в базе
- `password_hash` — пароль хранится только в виде хеша (SHA-256 + соль)

#### 2. roles.json — Роли

```json
{
  "id": "role-admin",
  "name": "admin",
  "description": "Администратор — полный доступ ко всему",
  "permission_ids": [             // ← список разрешений
    "perm-users-read",
    "perm-users-write",
    "perm-cars-read",
    ...
  ]
}
```

**Ключевые поля:**
- `permission_ids` — связывает роль с разрешениями (отношение Many-to-Many)

#### 3. permissions.json — Разрешения

```json
{
  "id": "perm-cars-read",
  "resource": "cars",      // ← НА ЧТО можно действовать
  "action": "read",        // ← ЧТО можно делать
  "description": "Просмотр автомобилей"
}
```

**Ключевая идея:** разрешение = ресурс + действие.
- `resource` — объект системы (users, cars, roles, permissions)
- `action` — что с ним делают (read, write, delete, manage)

#### 4. sessions.json — Чёрный список токенов

```json
{
  "token": "eyJhbGciOi...",
  "user_id": "user-1",
  "logout_at": "2024-01-01T12:00:00"
}
```

Зачем нужен? JWT-токен — самодостаточный, сервер не хранит сессии.
Чтобы "разлогинить" пользователя, мы записываем его токен в чёрный список.
При каждой проверке токена мы смотрим — нет ли его в этом списке.

### Диаграмма связей

```
┌─────────────┐     role_id     ┌─────────────┐   permission_ids   ┌──────────────┐
│   users     │────────────────▶│    roles    │───────────────────▶│ permissions  │
│             │  (Many-to-One)  │             │   (Many-to-Many)   │              │
│ id          │                 │ id          │                    │ id           │
│ email       │                 │ name        │                    │ resource     │
│ password_   │                 │ description │                    │ action       │
│   hash      │                 │ permission_ │                    │ description  │
│ role_id  ───┤                 │   ids    ───┤                    │              │
│ is_active   │                 └─────────────┘                    └──────────────┘
└─────────────┘

┌─────────────┐
│  sessions   │  ← чёрный список отозванных JWT-токенов
│             │
│ token       │
│ user_id     │
│ logout_at   │
└─────────────┘
```

### Как проверяются права (алгоритм)

Когда пользователь обращается к API:

```
1. АУТЕНТИФИКАЦИЯ: "Ты кто?"
   ├── Достаём JWT-токен из заголовка Authorization: Bearer <token>
   ├── Расшифровываем токен → получаем user_id
   ├── Проверяем, что токен не в чёрном списке (sessions.json)
   ├── Находим пользователя по user_id
   └── Проверяем, что is_active=True
   
   Если не прошло → 401 Unauthorized

2. АВТОРИЗАЦИЯ: "Тебе можно?"
   ├── Находим роль пользователя по role_id
   ├── Получаем все разрешения этой роли
   ├── Ищем разрешение с нужным resource и action
   └── Если нашли → доступ разрешён
   
   Если не нашли → 403 Forbidden
```

## Как тестировать в Swagger UI

1. Открой http://localhost:8000/docs
2. Зарегистрируйся или залогинись через POST /users/login
3. Скопируй токен из ответа
4. Нажми кнопку "Authorize" (замочек) вверху страницы
5. Введи токен в поле (без "Bearer", просто токен)
6. Теперь можешь вызывать защищённые эндпоинты

## О безопасности

### Хеширование паролей
- Используется SHA-256 + случайная соль (модуль hashlib из стандартной библиотеки)
- Пароль НЕ хранится в открытом виде
- Формат хранения: "соль:хеш"

### JWT-токены
- Используется PyJWT с алгоритмом HS256 (HMAC + SHA-256)
- Токен содержит: user_id (sub), время создания (iat), срок действия (exp)
- Токен подписывается секретным ключом — подделать нельзя
- Срок действия: 24 часа

### Logout
- Токен добавляется в чёрный список (sessions.json)
- Даже если токен не истёк — он не принимается после logout

### Коды ошибок
- **401 Unauthorized** — не передан токен, токен невалиден/просрочен/отозван, пользователь не найден/удалён
- **403 Forbidden** — пользователь определён, но нет прав на запрашиваемый ресурс
